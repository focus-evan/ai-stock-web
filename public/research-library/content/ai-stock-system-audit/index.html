Scope & method

范围与审计口径

本报告把“有页面”“有接口”“有缓存数据”“当前线上可用”“可以安全依赖”拆成五个不同层级。只有代码、测试、依赖和运行状态能够互相印证时，才标记为稳定。

代码盘点

核对路由、服务、数据源、仓储、调度、部署脚本、近期提交和遗留兼容路径；不把注释和旧 README 当成事实。

可执行验证

运行 Python 编译、核心测试、完整测试发现、前端类型检查、Vitest、ESLint 和生产构建，记录真实通过与失败边界。

线上冒烟

仅执行 GET：前端、健康、数据库、调度、北向、短线四法、组合、影子股、产业链、IPO统计与 RAG 集合；未触发刷新或交易。

i
边界说明审计的是这三个当前仓库。旧“维度更新 / 财报联动”页面代码在前端仍有残留，但 /system/sync 已被路由层明确退休，且前端仍声明的 /system/sync/history、/sync/stock、/sync/ipo 在当前后端没有对应接口，因此不能算作当前稳定功能。
Executive conclusion

总体结论：功能可用，但工程可信度尚未跟上功能密度

系统已经从“战法展示工具”演进为包含数据网关、14 个活跃策略、模拟组合、跟进归因、自进化和 AI 研究能力的完整平台。新近建设的北向五层雷达和短线四法具备较好的数据语义与单元测试基础；真正限制下一阶段的不是缺少功能，而是安全边界、发布可信度、健康检查、缓存迁移和系统拆分。

应立即收敛的方向

旧策略与 Skill 策略双轨、应用内散落 DDL、可选认证、宽前缀通用网关、超大接口响应、前后端残留同步接口和无法失败的 CI。

数据链路优势

网关已引入专用端点、重试、缓存、stale 回退、206 partial、北向多层来源状态；后端对北向“官方事实 / 无方向活跃度 / 模型估算 / 代理信号”进行了语义分离。

数据链路断点

网关公网不可验证、API 健康不包含网关；大量后端模块仍可直接 AKShare 回退，导致来源和失败口径分散；部分旧缓存缺少版本和执行政策。

交易链路优势

调度器有北京时间、任务持久状态、窗口恢复、隔夜强退、候选触发复检、短线四法信号账本和跟进/进化样本隔离。

交易链路断点

调度器仍是单进程 30 秒轮询的大文件；交易日判断仅周一至周五；补跑未传递不可执行语义；接口、任务、缓存、交易未形成统一 trace 与 release revision。

北向五层雷达当前最佳实践季度持仓、官方活跃度、外部 ETF、全球风险、境内代理分层，LKG 缓存和部分状态。ETF 份额/全球风险线上缺失；网关就绪未纳入主健康。补源健康 SLO，不把缺失层硬补成方向信号。

模拟组合与交易可用但有权限风险14 个组合、持仓、交易、收益、结算、复盘、自动交易和隔夜生命周期。认证可选；无 token 时 user_id=None；admin/evan 特例写死；大屏过重。P0 强认证，P1 租户隔离和读模型。
自选、操作指导、滚动降本可用但需约束自选、指导历史、整体分析、解套计划。LLM 输出和行情数据质量决定操作层；接口无清晰用户隔离。明确“事实缺失即不生成价格指令”，补用户域。
战法跟进与不可变历史方向正确trade/watch 分账、快照、绩效、信号账本、revision。signal revision 尚未贯穿订单、成交、收益和进化记录。P1 打通端到端血缘。
策略自进化受控试验阶段状态、运行、冻结、回滚、有效样本过滤、费用参数。尚无完整 point-in-time 回测、对照组、容量/滑点和参数审批。只允许 shadow 模式晋级，设样本与显著性门。
调度器运行中但复杂北京时间、任务持久化、恢复、30 秒轮询、失败重试、过期原因。单进程大循环；交易日仅按工作日；任务互相占窗口；注释与实际时间漂移。任务表+worker+交易日历+lease。
移动端策略覆盖不完整10 个传统策略移动页面。短线四法只在统一桌面页，移动端与桌面字段容易漂移。共享 schema renderer，不再复制页面逻辑。
数据网关韧性强，边界弱44 路由、多源、缓存、stats、ready、北向持久层。无鉴权、CORS *、宽前缀万能代理、外部不可达、内存统计多 worker 不聚合。P0/P1 收紧访问面并集中指标。
部署与发布不具备强门禁前端 GitHub Actions 自动部署，三个仓库均有脚本/容器配置。后端/网关无 CI；前端测试 continue-on-error；无 lint；install 非 frozen；无跨仓版本。P0 建立可失败的统一发布门。
Strategy system

战法体系：从“推荐列表”走向“可归因信号”，但仍需收敛双轨

当前调度器的 ACTIVE_STRATEGIES 有 14 个：10 个传统策略与 4 个 Skill 短线战法。详细规则已另有 AI Stock 战法手册，本节只审计系统级一致性。

层级策略优势系统性问题
情绪/龙头dragon_head、emotion_relay、养家、92科比、陈小群、北京首板时点与角色逐渐清晰，Skill 已有执行席位和 T+1 样本。传统龙头/情绪与 Skill 在候选、组合和页面上并存，容易重复暴露、重复下注和重复归因。
趋势结构breakthrough、volume_price、moving_average、trend_momentum规则化程度较高，适合统一事实层与组合赛马。评分口径和持有周期不同，综合策略若只按分数合并会产生不可比问题。
事件与隔夜event_driven、overnight事件有催化语义；隔夜已具备二次确认、强退和成交反馈。事件时间戳、公告可信度、隔夜真实可成交与涨跌停约束仍需统一。
资金与元策略northbound、combined北向来源语义最佳；综合已避免把隔夜与中短线混为同一时间框架。综合仍依赖各子策略缓存质量；北向缺层时需要组合权重自动收缩而非静态打分。
!
短线四法补跑缺陷调度器识别了 catchup_due，但调用服务时仍传原始 session_type，没有追加 _catchup。而服务只有在请求类型以 _catchup 结尾时才关闭开仓门。结果是 10:35 补跑 10:05/10:15 任务时，理论上仍可能被当成主检查点有效信号，并在尚未结束的交易窗口进入组合。现有测试只验证“当前任务优先于旧补跑”，没有验证“补跑绝不产生可执行推荐”。
!
北京首板 14:20 语义噪音服务层正确把 seal_check 设为 validation-only 且降级买入项；但调度器仍配置第二个 seal_check trade task，测试还明确要求这两个交易时段都存在。即使最终没有推荐可买，也会制造“下午交易任务”的状态和日志。应删除该交易任务，保留验收/失效/持仓管理任务，令实现与文档一致。

策略系统下一步应统一的 6 个主键

  • strategy_revision：策略逻辑与参数版本。
  • signal_revision：不可变信号版本，已在 Skill 中实现。
  • data_snapshot_id：生成信号时的事实快照与 as-of。
  • execution_decision_id：组合为何买/不买/等待。
  • order_fill_id：真实或模拟成交、费用、滑点。
  • evaluation_sample_id：收益归因与进化样本，必须能反查前五者。
Data & AI

数据与 AI：来源变多不是目标，可证明的数据契约才是

行情与技术数据

已有腾讯/新浪/东财/AKShare 多源和网关回退。问题是不同模块各自降级，字段、时间、复权和“空数据”含义不统一。

财务与基本面

理杏仁、财报业绩表、同花顺摘要、财务指标均已接入。当前缺少报告期主键、公告日、可见日和跨源冲突决议。

LLM 与 RAG

主/备 LLM、重试、熔断、RAG、多集合和日志很丰富。但 Qdrant 失败仍假绿，AI 生成常与同步 HTTP 请求耦合。

建议的数据质量契约

字段必须含义失败时行为
observed_at系统抓到该值的时间。缺失则不能宣称实时。
data_as_of数据事实对应的市场/报告时点。超过各类 SLA 标记 stale。
available_at历史回测中当时真正可获得的时间。缺失不得用于 point-in-time 回测。
source_id/source_url具体来源，不只写“AKShare”。来源不明不得作为强证据。
evidence_typeofficial_fact / no-direction activity / model_estimate / market_proxy。禁止把代理改写为官方净买入。
quality_statusok / partial / stale / unavailable / conflict。策略权重收缩或直接关闭执行门。

Critical findings

最需要深刻优化的 12 个点

级别问题为什么重要根因目标状态
P0真实密钥被 Git 跟踪后端的 LLM、数据库、Embedding、理杏仁等 secret-like 值存在于已跟踪的 .env/.env.local/.env.main。只忽略了虚拟环境，没有忽略后端 .env；部署依赖仓库内环境文件。撤销轮换、从当前树和历史清理、改用 secrets manager，并加 secret scan。
P0服务端授权缺失用户/角色/菜单 CRUD、调度触发、缓存清理、策略刷新、组合操作可绕过前端权限。“内部任务兼容”演变为可选认证和无认证路由。所有路由默认认证；内部任务使用 service identity；高风险操作要求 admin + audit log。
P0健康检查假绿RAG 已 500、网关不可验证，overall 仍 healthy，会掩盖真实故障。liveness、readiness、dependency health 混用且遗漏依赖。liveness 只看进程；readiness 检查 DB/Redis/Qdrant/网关；业务新鲜度另做 SLO。
P0Skill v9 缓存污染 v10 展示review 旧缓存仍带 direct buy，session policy 缺失，容易造成操作指导冲突。代码升级没有配套缓存迁移/失效/重建。逻辑版本不匹配时 recommendations 强制为空，只保留候选和迁移提示；部署后预热 v10。
P0catch-up 仍可被当成执行检查点错过 10:05/10:15 的信号可能在稍后补跑时重新打开买入门。调度器计算 catchup 但未传 session_type_catchup。补跑只生成 stale_recheck；执行器再次验证 checkpoint revision 和时效。
P0发布门禁不能失败测试红灯仍可部署，后端/网关改动没有自动测试。前端 test continue-on-error；无统一 CI。三仓 PR/主分支均强制 lint/type/test/build/secret scan；任何失败阻止发布。
P1单体和超大文件7,153 行 main、2,162 行 system endpoints、1,735 行前端策略 API 增加回归概率。按需求叠加，没有按领域边界拆服务。composition root + routers + domain service + repository；前端按领域拆 client/schema/query。
P1DDL 散落在运行路径线上 schema 状态不可重现，启动失败只能非致命跳过或临时 ALTER。缺 migration registry 和 schema version。单一有序 migration 工具，启动只校验版本，不自行改表。
P1网关访问面过宽CORS *、无认证、万能代理允许几乎所有 stock/bond/fund/macro 等函数，容易被滥用拖垮上游。把开发便利接口直接暴露到生产。内网/VPN、mTLS 或 API key、精确函数 allowlist、限流、请求成本预算。
P1响应模型过重大屏和 Skill 页面 15–17 秒，用户会重复点击并放大后端压力。列表接口混入全量明细、历史、LLM 文本和持仓。摘要接口 P95 < 800ms；详情按需；ETag、gzip、服务端缓存。
P1测试分类混乱单元、CLI、线上烟测、外部数据库测试混在 pytest 默认发现，真实回归信号被噪音淹没。缺 pytest.ini markers、fixture、目录规范。unit/contract/integration/live 分层；默认 CI 只跑确定性测试，live 单独调度。
P2策略进化缺因果与容量约束胜率提升可能只是行情阶段、选择偏差或不可成交收益。虽有样本门，但缺完整 PIT、对照组、费用、冲击和容量。shadow → challenger → champion 晋级，带显著性、稳定性、容量和回滚阈值。

P0 · 0–7 天 安全与真实性止血

密钥事件处理

立即撤销并轮换 Git 中出现的 LLM、数据库、Embedding、理杏仁等凭据；删除跟踪的环境文件，使用 GitHub/Ali云 secret；用 git-filter-repo 清历史并通知所有协作者重新同步。

建立 require_user、require_admin 和 service identity；先保护系统 CRUD、调度、缓存、策略 refresh、组合写入、跟进/进化写入、网关通用代理；匿名只开放 liveness 与必要只读公共接口。

旧逻辑缓存强制无执行推荐；部署时预热 v10；catch-up 传递专用 session 类型；执行器校验 can_open_new_position、checkpoint、生成时间和 signal revision。删除 14:20 新开仓任务语义。

健康检查纠真

拆 /live、/ready、/health/dependencies、/health/data-freshness；Qdrant 断连不能 overall healthy；指标返回真实 CPU/内存/磁盘/进程 uptime。

可失败发布门

清理默认测试集合，三仓 CI 强制执行；前端移除 test continue-on-error，使用 frozen lock，加入 lint；发布产物写入 commit SHA、schema version、build time 和依赖锁 hash。
