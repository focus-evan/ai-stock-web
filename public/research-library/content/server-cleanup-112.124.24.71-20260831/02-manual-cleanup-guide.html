服务器优化：手动逐步操作手册

围绕旧 Dify 1.7.1 生产平台，逐步完成引用核验、回收副本清理、Docker 缓存/镜像清理、日志限额、状态告警和最终验收。

重要
这是已经执行成功的服务器专用手册，不应在当前状态下从头重复运行。 回收站、镜像和缓存已经清理；旧0.15.3版本删除与ESSD启用见第04章。

执行原则与停止条件

  • 13 个容器全部处于运行状态，不执行 docker rm、docker stop 或 compose down。
  • 不处理 /dify/dify1.7.1/dify/docker/volumes，这是当前生产数据库和插件数据。
  • 不删除 /home/dify15/dify-0.15.3-back，只删除已证明重复的回收站副本。
  • 不直接 truncate、rm、gzip 运行容器的 JSON 日志。
  • 每个写操作前先保存原配置和清单；输出不符合预期时立即停止。
  • Docker 清理和压缩使用 nice/ionice，降低正常业务影响。
禁止：不要运行 docker system prune -a --volumes，不要递归删除 /var/lib/docker，不要删除 Dify PostgreSQL/Weaviate/plugin_daemon 数据目录。

6

在多重路径保护下清理回收站

影响：永久删除回收站内容；原始 0.15.3 备份保留在 /home/dify15。
只允许删除 /.Recycle_bin 的一级子项
set -euo pipefail
recycle_root=/.Recycle_bin
audit_dir=/var/backups/server-cleanup-112.124.24.71-manual-20260831-1200

test "$(realpath "$recycle_root")" = "$recycle_root"
test -d "$audit_dir"
if timeout 30 lsof +D "$recycle_root" 2>/dev/null | grep -q .; then
  echo '回收站有打开文件'; exit 1
fi
if findmnt -R "$recycle_root" 2>/dev/null | grep -q .; then
  echo '回收站包含挂载'; exit 1
fi

mapfile -d '' recycle_entries < <(find "$recycle_root" -mindepth 1 -maxdepth 1 -print0)
test "${#recycle_entries[@]}" -gt 0
: > "$audit_dir/recycle-top-level-deleted.txt"

for recycle_entry in "${recycle_entries[@]}"; do
  resolved_entry="$(realpath -m "$recycle_entry")"
  case "$resolved_entry" in
    "$recycle_root"/*) ;;
    *) echo "异常目标：$resolved_entry"; exit 1 ;;
  esac
  printf '%s\n' "$resolved_entry" >> "$audit_dir/recycle-top-level-deleted.txt"
done

rm -rf -- "${recycle_entries[@]}"
test -z "$(find "$recycle_root" -mindepth 1 -maxdepth 1 -print -quit)"
du -sh "$recycle_root"
df -h /

本次结果：回收站约 12.55 GiB → 4 KiB；根盘 92% → 81%。

7

清理 Docker build cache，保留 5 GB

影响：不影响已运行容器；后续构建可能重算缓存。
无 active build 时执行
active_build_pids="$(ps -eo pid=,comm=,args= | awk '$2 == "docker-buildx" || ($2 == "docker" && $3 == "docker" && $4 ~ /^build/) {print $1}')"
test -z "$active_build_pids" || { echo "有 active build：$active_build_pids"; exit 1; }

docker system df
timeout 300 ionice -c3 nice -n 19 \
  docker builder prune -af --filter until=24h --keep-storage 5GB
docker system df
df -h /

注意：镜像删除后 Docker 可能重新计算部分层为 build cache，因此第 8 步后应再执行一次本步骤。本次两轮报告合计释放约 13.45 GB。

9

限制 systemd journal 到 1 GiB / 14 天

影响：journald 重启；业务容器不重启；被 vacuum 的旧日志不可恢复。
安装配置并收敛
install -d -m 0755 /etc/systemd/journald.conf.d
install -m 0644 /tmp/journald-99-resource-limits.conf \
  /etc/systemd/journald.conf.d/99-resource-limits.conf

systemctl restart systemd-journald.service
systemctl is-active systemd-journald.service
journalctl --rotate
journalctl --vacuum-time=14d
journalctl --vacuum-size=1G
journalctl --disk-usage

配置文件可从文档集下载：journald-99-resource-limits.conf。本次 journal 从 1.2 GiB 降至 49.6 MiB。

10

设置新建容器 JSON 日志默认上限

影响：Docker daemon 只 reload，不 restart；已有容器参数不追溯变化。
Docker 20.10 使用 jq 校验 JSON
audit_dir=/var/backups/server-cleanup-112.124.24.71-manual-20260831-1200
cp -a /etc/docker/daemon.json "$audit_dir/daemon.json.before-log-limit"

jq '. + {"log-driver":"json-file","log-opts":{"max-size":"100m","max-file":"5"}}' \
  /etc/docker/daemon.json > /tmp/daemon.json.new
jq empty /tmp/daemon.json.new

install -m 0644 /tmp/daemon.json.new /etc/docker/daemon.json
systemctl reload docker.service
sleep 2
systemctl is-active docker.service
docker ps --format '{{.Names}}|{{.Status}}'
journalctl -u docker.service --since '5 minutes ago' --no-pager | tail -30
边界：当前 app_api_1 等历史 JSON 日志不会自动缩小。为了零中断，本次不重建容器、不直接截断；第11步负责状态告警。

保留原安全 watchdog，追加周期维护

影响：只增加两条任务；原每分钟反恶意 docker-daemon watchdog 完整保留。
安装维护脚本并更新 crontab
audit_dir=/var/backups/server-cleanup-112.124.24.71-manual-20260831-1200

bash -n /tmp/bzsj-docker-maintenance.sh

tmp_cron=/tmp/bzsj-root-crontab.new
(crontab -l 2>/dev/null || true) |
  grep -vE 'bzsj-resource-guard\.sh|bzsj-docker-maintenance\.sh' > "$tmp_cron" || true
printf '%s\n' \
  '*/10 * * * * /usr/local/sbin/bzsj-resource-guard.sh' \
  '27 3 * * 0 flock -n /run/bzsj-docker-maintenance.lock ionice -c3 nice -n 19 /usr/local/sbin/bzsj-docker-maintenance.sh' \
  >> "$tmp_cron"
crontab "$tmp_cron"
crontab -l

维护脚本：bzsj-docker-maintenance.sh。有真实 active build 时自动跳过；否则保留5GB缓存并清理30天前未引用镜像。

配置回滚说明

配置可回滚；已删除的回收站、旧镜像和缓存不能原地恢复。

对象回滚方法限制
daemon.json恢复 $audit_dir/daemon.json.before，用 jq 校验后 systemctl reload docker。不要 restart Docker；已删除镜像需重新拉取。
root crontabcrontab "$audit_dir/root-crontab.before"会移除资源守卫与周维护。
journal 限额删除 drop-in 并重启 journald。已 vacuum 的历史日志不可恢复。
回收站服务器归档保留完整文件清单和重复性证据。内容本身已删除；原始 0.15.3 备份仍位于 /home/dify15。
镜像/缓存从镜像仓库重新拉取或重新构建。本地已清理层不可直接恢复。
