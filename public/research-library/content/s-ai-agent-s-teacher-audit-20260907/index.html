s-ai-agent：让每次判断更接近 S 老师

2026-09-07 · 架构与行为审查 · 基于远程 prod 分支、核心源代码与 S 老师语料

我的判断：s-ai-agent 已经具备构建 S 老师 AI 助教的业务基础，但目前主要依赖不同入口各自组合提示词、知识片段和模型调用。最值得优先建设的是一套所有入口共用、可验证的 S 老师决策机制。

“更接近 S 老师”应当落实为：遇到同一情境，抓住相近的关键矛盾，选对研究方法，尊重相同的证据标准与资金约束，在条件变化后合理改变判断，并以适合受众的方式表达。语气相似只占其中一部分。

这份报告把“AGI 视角”落实为目标理解、知识与环境建模、规划与工具使用、记忆、判断校验、受控学习六种能力。不把增加 Agent 数量、知识库规模或模型参数量作为能力提升的直接证明，也不承诺每个回答都能等同于 S 老师本人。

02 · 已经值得保留的基础

当前工程并非缺少有用能力。升级时应复用已经有效的部分，逐步收拢共同规则。

现有资产 代码中的实际能力 下一步如何使用

F01 · 固定公司演示会抢先处理真实问题

代码事实与隔离复现。 is_mabu_summary_demo_enabled() 在未配置时默认返回开启；检测词包含 S40、公司价值评估、马步小结、研判报告 等通用词。命中后使用固定的绿的谐波演示主题。普通联网入口在常规检索之前就尝试返回演示结果。

隔离输入 默认开关下的检测结果
请按 S40 分析贵州茅台 命中固定演示主题
请写宁德时代的公司价值评估 命中同一个演示主题
请给腾讯做马步小结 命中同一个演示主题
解释安全边际 不命中

这些是路由函数的执行结果，不是线上模型回答截图。线上若明确关闭开关，相关风险路径不会按默认行为触发。

**建议：**演示限定在明确的演示用途、授权身份和指定实体；正常问答根据实体、数据时点、方法版本建立独立缓存。任何缓存返回都核对“用户问的对象”和“报告对象”。恢复研究流程比继续调整语气提示词更优先。证据：E01。

F02 · 被否定的回答也被当作学习材料

代码事实与隔离复现。 /training/compile 调用 get_all_recent_qa_for_compile，选取最近记录，不要求评分或已审核状态；纠偏为空时使用原始 AI 回答。随后以“学习 S 老师表达方式和思维框架”的说明注入提示词。

使用内存假数据执行实际编译函数的写入前部分，确认 1 星答案和未评分答案都会进入示例块。没有查询真实反馈库，不据此推断线上已累积多少错误样例。

**建议：**候选样例必须带审核人、审核状态、适用任务和来源。正例只收已批准的答案；低分记录保留为带错误原因的反例，不能原样混作正例；未评分记录保持待审。点赞或 5 星也不能单独证明它是 S 本人观点或当前事实。

每次纠偏至少记录：错在抓问题、选方法、取证、权衡、用户约束还是表达；保留原答、修订答、修改原因和适用条件。证据：E02。

F03 · 训练发布缺少版本、范围与回归闸门

代码事实。 编译会截去旧示例块，把最近一批记录直接更新到五类模板；更新 SQL 按 template_key 写入，没有在此路径创建新的可回退版本。课程学习、语音和通用问答得到相同的整块示例，离线 free_style、离线 cards 和资产配置等入口又不在同一覆盖范围内。

5 星记录还会生成 Wiki 主题并异步写入 base 集合，而该集合在多集合检索中不做时间衰减。这可能把某个历史场景里的好答案变成持续被召回的通用知识。另有一个具体边界：未评分记录的 rating=None 会使五星彩样条件中的数值比较报错；异常被捕获，提示词更新仍可能已完成。

**建议：**改为“候选提炼 → 来源及权限审核 → 固定评测 → 小范围验证 → 发布版本 → 可回滚”。通用原则、表达示例、时点判断分开存储；检索少量任务相关案例，保留代表性旧案例，防止最近样例覆盖长期原则。提炼结果先成为提案，不直接写进生效提示词。

在已检查的训练路由中未发现显式鉴权依赖，外部网关是否已保护尚未验证。因此需要核实“谁能提交纠偏、谁能发布”，并让发布权限在服务内也可审计；这不是已经证实的公网未授权漏洞。证据：E03、E16。

F04 · 记住了最近聊天，但没有稳定地记住当前任务

代码事实。 普通问答和联网问答调用 get_recent_chats_by_user_and_type(user_id, question_type, limit=5)。该方法不接受 session_id；仓库内已经有按用户和会话查询的另一方法。

风险有两个方向：同一个人在两个会话里讨论不同公司的问题，最近记录可能混入；同一个任务从语音切到卡片，按 question_type 切分的历史又可能不连贯。不能把它描述成已经证实的跨用户泄露，也不能把“有 Redis”直接视为语义记忆已经解决。

**建议：**会话记忆按 tenant + user + conversation + task 隔离；跨会话只读取经过确认的用户长期资料。维护“正在解决什么、已经核实什么、哪些假设已被推翻、下一步缺什么”的结构化任务状态。用户修正金额、期限或研究对象时，原值应标记已替代，并触发受影响结论重新计算。证据：E04。

F05 · 同一个人格目标，实际用了多套上下文

代码事实。 训练端使用 training_master、课程优先检索、一跳图扩展和会话消息；普通联网问答采用另一检索配置、按用户取历史，将模板、历史、问题、资料合并为一条 user 消息；学霸模式另有硬编码提示词和课程定位。

**建议：**把共同部分收敛到一个 DecisionEngine：相同的原则版本、任务状态、证据合同与质量检查。语音、卡片、长报告只更换表达层和篇幅预算。训练端调用同一个引擎，并额外挂接标注与对照评测；不要让训练页成为另一套产品。

模板指令用合适的指令角色承载；用户内容、历史、检索资料保留自己的身份。资料中的指令式文本不能提升为系统规则。证据：E05。

F06 · 越新并不等于越相关，也不等于仍然成立

代码事实与公式复现。 当前最终分数是“语义相似度 + 时间加成”。实时集合当天最高加 1.5，其他集合最高加 1.0。先召回候选，再按这一分数统一排序、截取最多 8 段。

用假设候选验证实际函数：一年前、相似度 0.9 的方法论得分约 0.960；当天、相似度 0.2 的视频得分 1.700。未来日期被截成距今 0 天，也获得完整加成。这个例子证明排序可能倒置，不表示真实库里两条具体文档的分数。

**建议：**先按问题选择证据类型，再做相关性门槛、关键词与语义联合召回、去重、重排。原则库按权威性和适用性选择；市场观点按有效期、适用市场与条件选择；实时事实按信息截止时间选择。对历史问题实施 published_at <= as_of，避免使用未来信息。不要用一个半衰期代替全部时效判断。证据：E06。

F07 · 还没有让所有回答经过真实的判断闭环

代码事实与结构性判断。 普通联网入口主要执行检索、组装提示词、一次模型调用和输出处理；它没有强制生成结构化研究缺口、再补证、再检查结论。后端启用 web search 并不能证明每个关键主张都经过查证。

仓库有 langgraph_agent.py，但静态扫描当前 API 文件（排除旧 main_original.py）未发现其工厂函数调用。该实现自身只有 agent 与 tools 循环，没有显式保存决策状态的检查点；当不存在充分性检查函数时，还会默认“知识充分、置信度 0.8”。StepExecutor 的 validate 方法返回的是验证指令描述，也不能当作已经执行验证。

**建议：**复杂问题走“任务识别 → 方法选择 → 证据收集 → 候选结论 → 反证检查 → 决策记录 → 表达”。简单知识问题可直接走短路径。证据不足时允许继续研究、给条件性结论或提出一个必要问题；置信度来自证据覆盖和历史校准，不写死一个数。

保存的是简明、可审核的判断依据和工具结果，不要求提取模型隐藏的思维链。证据：E08、E05。

F08 · 历史课堂背景被写成长期常量

代码事实。 学霸模式课程基准日期固定在 2026-04-30，提示词沿用对应期次；资产配置系统提示词把“2026 年 AI 全产业链进入全面爆发期”作为预设背景。语音示例还把“市盈率最好低于二十倍”作为通用表达示例，容易在学习语气时顺便学走估值判断。

教学标准答案本身可以保留，但必须绑定课程、日期、适用场景与批准人。不能只因为它是课堂答案，就推断为当前所有学员的投资结论。

**建议：**长期原则与可变判断分开：市场背景从有时点的事实和已确认观点读取；课程日期从用户当前课程上下文读取；数字化示例使用带条件的真实案例或无投资含义的表达例子。遇到与历史判断相反的新事实，应解释变化条件。证据：E09。

F09 · 模型降级可能同时丢失研究能力

代码事实。 统一模型路由已经做了实际模型记录，这是正确基础；但 fallback 分支会移除部分 tools、response_format 等参数，DashScope 相关分支不会按同样方式携带 web search 开关。默认普通问答允许降级。

**建议：**请求声明必须具备的能力，例如实时证据、结构化输出、计算核验或指定模型。候选模型不满足能力时，先由独立工具完成取证或验证；做不到就返回明确的受限状态。主模型与备用模型分别进行 S 老师一致性评测。传输成功、语气自然、任务完成是三件需要分别验收的事。证据：E07。

F10 · 知识很多，但概念身份与观点身份需要整理

本地文件统计。 1,638 个 Markdown 文件中有 1,169 个主题页、419 个来源页、44 个实体页；发现 75 组完全相同的主题标题。例如“AI 算力国产替代”对应五个不同文件名。

被扫描主题的 frontmatter 都有 evidence_count、aliases、last_updated，但没有发现本次检查的 speaker、approved_by、valid_from、valid_to 等显式字段。这不代表正文没有来源，也不能代表线上向量库的质量。重复标题也须先判断是别名、重建残留还是有意保留的不同版本。

WikiGraph 当前解析的是文档链接，并扩展一跳摘要；它尚不是能够表达“事件怎样影响成本、需求、竞争与利润”的因果模型。

**建议：**采用稳定的概念 ID；保留别名与历史跳转。每条知识标明来源角色：S 本人原话、S 已确认总结、团队整理、外部事实、模型推断。AI 生成的概括不能因进入 Wiki 就自动升级为 S 本人观点。进一步把重要关系表示成带证据和条件的断言，区分“相关”与“因果”。证据：审查数据、E10。

F11 · 缺少能回答“这次真的更像 S 老师吗”的基准

已检查范围的结论。 现有测试覆盖大量业务计算、接口兼容、模型路由与记录，但没有找到跨入口、固定留出案例、由 S 老师校准的判断一致性评测机制。训练评分统计也不能代替这样的评测：它容易受题目变化、重复曝光、评分尺度变化影响。

**建议：**先建立小而可信的基准，再改模型、检索和提示词。采用确定性校验、模型辅助评审和 S 本人盲评组合；评审既看回答，也看工具结果与最终业务状态。这个评测设计方向与 Anthropic 的 Agent 评估工程经验一致；第 08 节给出本项目的具体方案。

F12 · “已提交学习”与“已生效学习”没有统一状态

代码事实。 训练编译先提交数据库更新，再写本地 Wiki，再启动 asyncio.create_task 做向量更新；后台异常主要记录日志，接口里的触发状态不能证明入库已完成。通用 TaskManager 则把任务状态保存在进程字典中。

**建议：**使用持久化任务与 outbox，记录候选、审核、发布、索引中、已生效、失败、回滚等状态；写入幂等，重启可以恢复。知识包有统一版本，进程和副本读取同一版本。已有同步数据库与检索调用出现在 async 路由中，也应在性能预算内逐步移出阻塞路径。

这属于代码层面的重启及多进程风险，未进行线上容灾测试，不等同于已经证明某次学习丢失。证据：E12。

04 · S 老师究竟有哪些东西值得学习

S 老师的特点不能压缩为“说话直接、敢给观点”。本次对照的课程强调方法工具箱、能力圈、资金分阶段投入，以及人要主动抓问题、把 AI 当助手。已有方法论总览和投研方法页可作为索引；涉及原话或数字时仍需回到具体课程。

层次 应学习的内容 应避免的混淆
原则 内在价值、安全边际、能力圈、资金纪律，追问自己真正懂不懂 把某年看好的行业当成永远有效的原则
问题识别 用户卡在知识、研究、估值、配置、情绪还是执行 所有问题都套一份公司报告
方法选择 产业全景、政策、历史、新物种、标杆、竞争博弈、财报验证等工具 用单一评分模型替代全部思考
取舍顺序 先看清产业全景，做赛道与公司减法，再对少数候选深入研究 把“减法”做成机械删除低分股
判断条件 区分好赛道、好公司、好价格；加入期限、能力与资金约束 好公司自动等于任何人此刻都适合买

原始转写有 ASR 错误，因此本报告使用语义归纳，不把转写中的全部数字和专名当作已校准事实。创作流程应保留已确认顺序：小结 → 角度 → 提纲 → 填充 → 专业校准 → 视频化 → 虎头 → 模型沉淀。

**建设建议：**安排几轮以真实取舍为中心的 S 老师访谈。每个案例只追问四件事：你第一眼关注什么；哪项证据改变了选择；哪些信息缺失时你不下结论；什么变化会让你推翻判断。随后给同一案例变更一个关键条件，检验规则能否迁移。

这种从具体个人访谈与自述构建行为模型的方向有研究依据。Park 等人的个体模拟研究（2026 年修订版）比较了访谈、问卷及两者组合；它支持重视个人证据，但不能证明投资专家的复杂判断可以被完全复制，也不能把论文表现迁移成本系统的“相似度”。

05 · 建议的目标架构

理解任务谁在问 · 要解决什么 · 截止时点
选择方法S 原则 · 方法卡 · 用户约束
收集证据课程原文 · 当前数据 · 确定性计算
形成判断候选方案 · 关键权衡 · 反证
校验与表达检查结论 · 选择篇幅 · 保留来源

一个共同决策引擎，多种任务流程与表达方式。 是否调用多个模型或多个 Agent，由独立工作量和实测收益决定；初期一个规划器、确定性工具和验证器就能完成主要建设。

5.1 一份有版本的 S 原则包

包含稳定原则、冲突时的优先顺序、已批准的方法卡、任务相关示例及表达规范。它需要可追溯的来源和 S 老师确认，不能由一次模型总结直接定稿。原则、数据、历史观点分别更新，避免改一条市场观点时影响整个人格。

例如，事实不足时保持条件性判断，应优先于“要敢于给出明确观点”；先识别用户的钱能放多久，应优先于给出完整配置比例。这里给的是待校准的工程规则，不冒充 S 老师已经批准的原文。

5.2 把方法写成可执行的卡片

每张方法卡至少说明：何时使用、何时不用、必需信息、可调用工具、判断规则、停止条件、反例、来源与版本。例如“赛道到公司的研究”应要求行业范围与利润分布，再筛公司；“利润大增的判断”应检查基数、一次性收益、现金流和可比口径。

它们是引擎按问题选择的程序化方法，不要求每次把所有方法全文塞进提示词。精简且按需提供上下文的方向也符合 Anthropic 的上下文工程实践。

5.3 建立三种不同的知识读取方式

  1. 原则与方法：必须能准确检索稳定规则和适用条件，不因课程较老自动降权。
  2. 案例与观点：保存当时知道什么、为什么这样判断、后来如何验证；不能去掉时点后用于当前结论。
  3. 实时事实：使用来源、发布时间、口径与观测时间；数值由工具取得，计算由程序执行。

重要决策的每个关键主张都关联证据 ID。事实、观点、推断、未知分别表示；遇到冲突同时保留两个来源和冲突原因。资料正文属于待分析内容，不能成为可执行指令。

5.4 用四类记忆替代最近五轮聊天

记忆 内容 写入规则
当前任务 目标、对象、已验证事实、待办、已否定假设 任务范围内持续更新，保留事件顺序
用户资料 用户自己确认的期限、经验、表达偏好等 个人隔离、可修改可删除，不从单次情绪永久推断
S 方法与观点 原则版本、方法卡、S 确认的条件性判断 经过审核发布，历史观点保留有效区间
决策案例 情境、可选方案、简要依据、结果与修订 原始决策不可改写，结果另行追加

长对话压缩时必须保留纠错、否定、期限、实体和来源；不能只保留一个看似流畅的摘要。

5.5 让质量检查先于表达

先用确定性检查核对实体、单位、日期、共同季度、资金合计、权限与缺失值。再检查：关键结论是否有证据；反证能否推翻它；有无遗漏用户约束；是否需要补问或补查。最后才做语音或卡片表达。

同一份决策记录可以生成 100 字口语摘要、卡片和完整研究说明。输出转换后再次核对数字、方向、条件和风险边界是否被改写。不要在一句“说得更像 S 老师”的转换中重新决定能不能买。

5.6 使系统对行动结果负责

研究、教学、内容创作和业务执行使用不同的完成条件。读取完成不等于研究完成；生成方案不等于已确认方案；发送后台任务不等于数据已写入。涉及修改资产配置或其他业务状态时，行动范围必须绑定明确的用户意图与权限，完成后读取实际状态确认。

06 · 一次回答在新架构中应如何发生

以下是流程示意，不是本轮线上对比实测，也不是 S 老师本人确认的答案。

情境 系统首先需要判断 应调用的机制 合格的回答特征
“这家公司利润增长 180%，是不是很好？” 是持续经营改善、低基数还是一次性因素？ 单季度与累计口径检查、利润与现金流对照、行业比较 解释增长来源，列出当前能证明与不能证明的部分，再作条件性判断
“这笔钱半年后要用，但我怕错过行情。” 资金用途与期限是否先构成约束？ 用户资金事实确认、资金分桶与纪律方法 先回答资金约束与情绪问题；不能只根据行业热度选股
“老师昨天说的这条逻辑，现在还成立吗？” 指哪一段原话、哪个日期、条件是否变化？ 课程精确定位、历史观点版本、当前证据 清楚区分“当时说了什么”与“今天据此如何判断”
“上次金额说错了，是 30 万不是 300 万。” 哪些结论依赖被纠正的金额？ 任务状态更正、依赖重算、修改记录 更新所有受影响结果；不继续引用旧金额
“把这份行业资料做成口播。” 用户处在创作哪个阶段，核心问题是什么？ 小结、选题、填充与专业校准流程 有中心问题与叙事结构，专业核实发生在填充之后

系统内部建议保存这样的决策记录：

{

  "entity_id": "已确认的公司实体",
  "as_of": "本次信息截止时间",
  "principle_version": "s-principles-v1",
  "method_ids": ["growth-quality", "financial-comparability"],
  "facts": [{"claim": "已核实事实", "evidence_ids": ["e1"]}],
  "unknowns": ["需要进一步查证的事项"],
  "user_constraints": ["与本题相关且经确认的限制"],
  "alternatives": ["支持解释", "竞争解释"],

这是拟议结构，不是要求向普通用户展示技术字段，也不是要求模型披露隐藏推理。

07 · 训练闭环应怎样重建

第一步：收集取舍证据。 比起大量成片转写，S 老师对具体错误的修改理由、对边界案例的判断、对同一问题条件变化后的重新选择，通常更直接地对应目标能力。这是本项目的建设推断，需要对照评测确认收益。

第二步：形成成对案例。 同时保存原回答、认可回答、错误标签、修改理由、上下文与时点。把“观点错”“证据错”“对象错”“表达不顺”分开。团队提出的修改先标记为建议，不能自动等同于 S 本人批准。

第三步：归纳规则并保留反例。 例如从一次纠偏提炼出“这类问题先检查现金流”，同时标记何时不适用；不得从一次案例推出全行业、全时点规则。互相冲突的案例进入复核，而不是用最近一条覆盖旧结论。

第四步：统一运行与离线评测。 使用正式引擎重放案例；严格隔离训练、开发和封存测试集。案例按主题、来源会话、相似问题族分组，避免同一原文的改写同时进入训练和测试。

第五步：版本发布。 每个版本记录数据集、原则、方法、提示词、检索配置、模型与工具版本。通过后再小范围生效；出现决策回归可立即回退。不要让“训练成功”只意味着 SQL 更新成功。

第六步：追加结果与修订。 对市场判断保存当时信息与预测，后续再追加结果；对教学看学员能否正确应用；对创作看事实正确、结构和成片使用效果。投资判断的质量与短期涨跌分开，不能因为一次赚钱就奖励错误方法，也不能因为一次波动就推翻长期原则。

什么时候考虑微调？ 当经过审核的案例足够覆盖任务，而且在统一引擎、检索和提示词改进后仍存在可重复的行为偏差，再比较 SFT 或偏好优化与当前基线。先用高质量案例学习决策与表达；及时变化的价格、财报和市场观点继续交给外部证据。不能把未审聊天记录直接当作训练标签。

08 · 如何客观判断“更接近 S 老师”

建议先建设 200 个情境案例，作为第一版工程规模，数量可以按 S 老师可投入的时间调整：60 个投研、40 个配置与纪律、30 个课程答疑、20 个内容创作、30 个多轮纠错、20 个对抗及异常场景。它们尚未由本轮生成或评测。

按问题族分为 100 个训练、40 个开发、60 个封存测试案例；合成改写只能补充鲁棒性测试，不能伪装成 S 本人答案。先做少量重复标注，测清 S 本人的判断稳定性和团队评分差异。

维度 观察什么 建议的验收方式
决策一致性 核心结论、方法选择、取舍顺序是否合理接近 S 同情境与同事实下，由 S 盲评 A/B，不以文风代替判断
证据质量 关键主张有无对应来源、来源是否真能支持结论 自动检查日期与数值，抽样人工核验引用与推断
约束遵守 是否识别用户期限、能力、任务目标和权限 固定断言与业务状态校验，关键违规不被风格高分抵消
多轮能力 是否记住更正、维持对象、在新证据出现后修订 多轮案例和跨展示形式重放
表达与教学 是否清晰自然、适合对象、保留必要条件 人工偏好评审，检查口语化前后的语义一致性
运行稳定性 备用模型、超时、缺数据、重启时如何处理 故障注入与结果读取，记录完整率、耗时和成本

可以把“无跨实体错答、无未审核正例发布、无跨用户私有记忆混用”设为固定回归集的硬闸门；首轮发布候选可暂定 S 盲评偏好超过 70%、且置信区间下限超过 50% 为质量目标。这些是建议目标，当前没有达到与否的数据。 对 60 个测试案例给出样本数与置信区间；重复运行应按案例聚类分析，不能当成大量独立样本。

RAG 还应拆开看“检索是否拿到相关证据”“答案是否忠实于证据”“回答是否解决问题”。这种拆分可参考 Ragas 的原始评估论文，但模型自动评分不能替代 S 本人的价值判断。

推荐的对照顺序：当前版本 → 仅修正确性问题 → 统一原则与上下文 → 新检索与记忆 → 选择性复核 → 可选微调。一次只改变可识别的一组因素，分别测普通入口、卡片、语音、训练与备用模型。保留原始输出、评分人和版本，以便追查为什么变好或变差。
