服务器清理：手动逐步操作手册

按照“核验 → 备份 → 单项处理 → 单项验收 → 长期保护 → 总验收”的顺序执行。每个命令块可单独复制，不需要一次性运行整份脚本。

逐步操作每步可停止配置可回滚不重启业务服务
文档集入口01 清理前情况02 手动操作手册03 清理后情况
重要
这份手册记录的是已经执行成功的方案，但不能在当前服务器上从头盲目重跑。 两个旧容器已经删除、历史日志已经压缩。重复执行前必须重新做第 1–4 步并使用新的归档目录。

执行原则与停止条件

  • 一次只处理一个类别；每步完成后先验证，再进入下一步。
  • 不停止、不重建正在运行的业务容器；Docker daemon 只发送 HUP，不 restart。
  • 不删除 MySQL 数据目录，不对打开的 Java/Nginx 日志直接 gzip、rm 或 rename。
  • 任何配置文件修改前先复制到 /data2/archive/...，保证可回滚。
  • 如果命令输出与“预期结果”不一致，立即停止，不继续执行后面的清理命令。
  • 所有压缩任务使用 nice -n 19 与 ionice -c3，降低对正常业务的影响。
禁止：不要使用 docker system prune -a --volumes、不要递归删除 /var/lib/docker、不要直接清空正在运行容器的 JSON 日志、不要删除 /data2/mysql*_data。

配置 Nginx 与 catalina.out 安全轮转

影响：Nginx 只接收 USR1 reopen；Tomcat 使用 copytruncate，不重启 Java。
创建 /etc/logrotate.d/bzsj-data2
cat > /etc/logrotate.d/bzsj-data2 <<'EOF'
/data2/wwwlogs/*/*.log /data2/wwwlogs/*.log {
    daily
    maxsize 1G
    rotate 14
    missingok
    notifempty
    compress
    dateext
    create 0644 root root
    sharedscripts
    postrotate
        main_pid="$(systemctl show nginx.service -p MainPID | cut -d= -f2)"
        if [ -n "$main_pid" ] && [ "$main_pid" -gt 1 ]; then
            kill -USR1 "$main_pid"
        fi
    endscript
}

/data2/tomcat/prod/tomcat8-s50-job/logs/catalina.out {
    daily
    maxsize 1G
    rotate 7
    missingok
    notifempty
    compress
    dateext
    copytruncate
}
EOF

/usr/local/nginx/nginx -t
/usr/sbin/logrotate -d /etc/logrotate.d/bzsj-data2
停止条件：Nginx 配置测试或 logrotate dry-run 非 0，不能执行第 14 步的强制首次轮转。

替换旧的全盘 find 脚本，只压缩明确目录的关闭日志

影响：每天处理已关闭历史日志；lsof 会跳过 Java 正在写入的文件。
备份旧脚本并写入安全版本
audit_dir=/data2/archive/server-cleanup-manual-20260831-1200
cp -a /data2/scripts/clean-tomcat-log.sh "$audit_dir/clean-tomcat-log.sh.before-replace"

cat > /data2/scripts/clean-tomcat-log.sh <<'EOF'
#!/usr/bin/env bash
set -u

lock_file=/run/bzsj-legacy-log-clean.lock
exec 9>"$lock_file"
flock -n 9 || exit 0

compress_closed_logs() {
    scan_dir="$1"
    scan_pattern="$2"
    retention_days="$3"
    [ -d "$scan_dir" ] || return 0

    find "$scan_dir" -maxdepth 1 -type f -name "$scan_pattern" ! -name '*.gz' -print0 |
        while IFS= read -r -d '' log_file; do
            if ! lsof -- "$log_file" >/dev/null 2>&1; then
                gzip -f -- "$log_file"
            fi
        done

    find "$scan_dir" -maxdepth 1 -type f -name '*.gz' \
        -mtime "+$retention_days" -delete
}

compress_closed_logs /data2/tomcat/prod/tomcat8-s50-job/logs 'catalina.out-20*' 14
compress_closed_logs /data2/logs/stock '*.log.20*' 14
EOF

chmod 0755 /data2/scripts/clean-tomcat-log.sh
bash -n /data2/scripts/clean-tomcat-log.sh

与旧脚本的区别

  • 不再 find / 扫描整台服务器。
  • 不再对所有 catalina.out 用 cp + echo 直接截断。
  • 仅处理两个明确目录，并用 lsof 跳过打开文件。
  • 超过 14 天的压缩历史日志会删除，释放空间。

配置资源守卫与 Docker 大日志告警

影响：只读检查，异常时写入 journal；不主动删除文件。
创建 /data2/scripts/resource-guard.sh
cat > /data2/scripts/resource-guard.sh <<'EOF'
#!/usr/bin/env bash
set -u

root_used_pct="$(df -P / | awk 'NR==2 {gsub(/%/, "", $5); print $5}')"
data_used_pct="$(df -P /data2 | awk 'NR==2 {gsub(/%/, "", $5); print $5}')"
mem_total_kb="$(awk '/^MemTotal:/ {print $2}' /proc/meminfo)"
mem_available_kb="$(awk '/^MemAvailable:/ {print $2}' /proc/meminfo)"
mem_available_pct=$((mem_available_kb * 100 / mem_total_kb))

if [ "${1:-}" = "--report" ]; then
    printf 'root_used_pct=%s data2_used_pct=%s mem_available_pct=%s\n' \
        "$root_used_pct" "$data_used_pct" "$mem_available_pct"
    exit 0
fi

[ "$root_used_pct" -lt 85 ] || logger -p daemon.warning -t resource-guard "root filesystem usage is ${root_used_pct}% (threshold 85%)"
[ "$data_used_pct" -lt 85 ] || logger -p daemon.warning -t resource-guard "/data2 usage is ${data_used_pct}% (threshold 85%)"
[ "$mem_available_pct" -gt 10 ] || logger -p daemon.warning -t resource-guard "available memory is ${mem_available_pct}% (threshold 10%)"

find /var/lib/docker/containers -mindepth 2 -maxdepth 2 -type f \
    -name '*-json.log' -size +500M -print0 2>/dev/null |
    while IFS= read -r -d '' docker_log; do
        log_size="$(du -h "$docker_log" | awk '{print $1}')"
        logger -p daemon.warning -t resource-guard \
            "Docker JSON log exceeds 500 MiB: ${docker_log} (${log_size})"
    done
EOF

chmod 0755 /data2/scripts/resource-guard.sh
bash -n /data2/scripts/resource-guard.sh
/data2/scripts/resource-guard.sh --report

预期健康输出

本次最终为：root_used_pct=35 data2_used_pct=15 mem_available_pct=54。

对象回滚方法限制
Docker daemon.json从 $audit_dir/daemon.json.before 恢复，先 dockerd --validate，再对 daemon 发送 HUP。不重启业务容器；旧镜像需重新拉取/构建。
root crontabcrontab "$audit_dir/root-crontab.before"会移除本次新增的周期保护。
旧清理脚本将 clean-tomcat-log.sh.before 恢复到原路径。旧脚本存在全盘 find 和未压缩问题，不建议长期恢复。
logrotate 规则移除 /etc/logrotate.d/bzsj-data2 或恢复此前备份，然后 dry-run。已压缩历史日志不会自动解压。
journal 限额移除 drop-in，重启 journald。已 vacuum 的旧日志不可恢复。
旧容器日志完整 gzip 位于 $audit_dir/docker-retired-logs；inspect 元数据在同一归档目录。容器镜像若已 prune，需要重新拉取或构建后再重建容器。
